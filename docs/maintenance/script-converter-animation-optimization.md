# Script Converter 动画效果优化方案

最后更新: 2026-05-18

本文档记录 `script_converter` 智能体后续可实施的动画与演出优化方向，目标是提升生成的 WebGal 脚本在“节奏、镜头、表情、特效、音乐”上的整体完成度，而不是继续单纯堆叠语法规则。

## 问题判断

当前 `script_converter` 已经具备较强的规则约束，尤其在以下方面已经覆盖较多：

- 素材查询顺序
- 立绘切换时机
- `motion` / `expression` 合法性
- 场景切换流程
- `setTempAnimation` / `setTransform` 的数值约束
- BGM、滤镜、天气特效的使用规则
- 输出前自检清单

但目前更可能影响成片质量的，不是“缺语法规则”，而是以下三个结构性问题：

1. 缺少中间层的“演出规划”。
   现在模型往往一边理解剧情，一边直接输出 WebGal 指令，容易造成局部正确、整体节奏松散。

2. 动画知识仍以自然语言说明为主。
   即使知识库里已经有动画配方，模型仍可能每次临时自由组合，稳定性不足。

3. 缺少结果级演出质检。
   当前自检主要依赖同一个转换模型自我约束，缺少第二层对节奏和视觉质量的审查。

## 优化目标

这轮优化不追求“更多动画”，而追求以下结果：

- 动画使用更少但更准
- 情绪峰值更清晰
- 角色表演更连贯，不机械切表情
- 镜头、立绘、BGM、滤镜在同一段里有统一导演意图
- 输出脚本更稳定地符合 WebGal 实际演出习惯

## 核心方案

### 1. 增加“演出计划层”

最优先的改动，不是继续扩写提示词，而是要求 `script_converter` 在生成脚本前，先内部构建一份演出计划。

即使这份计划不直接写入结果文件，也建议在 prompt 中显式要求模型先按以下维度思考：

- `scene_goal`: 当前场景要传达的核心情绪或叙事目标
- `visual_mood`: 温暖 / 压抑 / 回忆 / 冲突 / 爆发 / 收束
- `bg_change`: 是否换背景，是否需要明显过渡
- `cast_layout`: 当前出场角色与站位
- `speaker_beats`: 哪些台词前需要切换表情或动作
- `camera_beats`: 哪些位置需要聚焦、推近、拉远、偏移
- `effect_beats`: 哪些情绪节点需要 `setTempAnimation`
- `music_beats`: BGM 进入、切换、淡出节点
- `pause_beats`: 哪些位置需要 `wait` 或留白

预期收益：

- 减少“指令正确但节奏散”的问题
- 让演出点集中在真正重要的位置
- 让脚本更接近“导演过的版本”，而不是“翻译过的版本”

### 2. 把动画知识改成半结构配方

建议把现有动画经验从“说明性文字”为主，逐步转成“配方库”为主。

推荐把常见情绪演出抽成固定模板，例如：

- `emotion_shock`
  - 当前说话角色切惊讶表情
  - 舞台轻微缩放或抖动
  - 短暂停顿

- `emotion_intimacy`
  - 角色距离拉近
  - 柔和滤镜
  - 节奏放慢，减少大幅运动

- `emotion_memory`
  - 去饱和或泛白
  - 转场变慢
  - 留白增加

- `emotion_conflict`
  - 左右角色对位拉开
  - 说话角色聚焦更强
  - 可用轻微压暗或紧张 BGM

- `emotion_reveal`
  - 在关键揭示点使用单次强演出
  - 先停顿，再强化视觉效果

配方库的目的不是替模型创作，而是限制它优先“选模板 + 填参数”，而不是每次重新发明动作组合。

### 3. 增加演出强度分层

当前容易出现的问题不是不会做动画，而是动画过密、过重、过于平均。

建议在 prompt 或知识库中引入“演出强度层级”：

- 普通对白段
  - 仅做轻量表情切换和少量站位变化
  - 不滥用 `setTempAnimation`

- 情绪推进段
  - 允许适量聚焦、位移、滤镜变化
  - 保持节奏连续，不堆叠重特效

- 高潮段
  - 允许单次明确强演出
  - 使用 `wait`、镜头、特效、音乐配合形成峰值

- 收束段
  - 效果逐步回落
  - 让画面回稳，避免全程紧绷

建议增加硬约束：

- 每个场景最多 1 到 2 个强演出点
- 非高潮段禁止连续叠加多个重特效
- 普通对话优先切表情，不优先动全舞台

### 4. 把角色演出触发条件从“句数”改为“情绪变化”

当前规则中“每隔 1~2 句切换一次表情或动作”有助于避免僵硬，但容易生成机械表演。

更推荐的原则：

- 当情绪、态度、关系变化时，切换 `expression` / `motion`
- 在情绪没有变化时，允许角色连续多句维持同一状态
- 让表情切换服务于“状态变化”，而不是服务于“频率指标”

换句话说：

- “切表情频率”只能作为兜底约束
- “情绪状态变化”应作为第一触发器

### 5. 增加结果级演出校验器

建议后续单独增加一个轻量 reviewer，专门检查转换结果的演出质量，而不是只检查语法正确性。

可选实现方式：

- 方案 A：新增一个 `script_reviewer` / `stage_reviewer` 智能体
- 方案 B：先做一个纯 Python 规则校验器

推荐优先覆盖以下检查项：

- `changeFigure` 是否都出现在对应台词前
- 角色再次出场前是否有淡入过渡
- 同一场景是否存在过多 `setTempAnimation`
- 是否有连续多个强特效叠加
- saturation / scale / transform 是否有恢复
- BGM 是否在场景切换后被合理处理
- 角色站位是否冲突
- 同一角色是否在短时间内高频切 motion / expression

注意：

这层 reviewer 的核心价值不在“查语法”，而在“查导演感和节奏控制”。

### 6. 建立“场景类型 -> 默认导演手法”映射

建议在知识库中明确整理不同场景类型对应的默认演出策略。

例如：

- 日常轻松对话
  - 少特效
  - 多表情变化
  - 少镜头运动

- 暧昧 / 靠近
  - 角色位移靠近
  - 柔和滤镜
  - 更平缓的节奏

- 冲突争执
  - 角色对位拉开
  - 聚焦更强
  - 可用轻微压暗或紧张音乐

- 回忆 / 自白
  - 去饱和
  - 慢节奏
  - 留白增多

- 爆点 / 揭示
  - 短促但明确的强演出
  - 先停顿，再释放

这份映射会帮助模型更稳定地“按场景类型套导演策略”，而不是每次自由发挥。

### 7. 中期方向：拆成“演出规划器 + 脚本转换器”

如果后续要进一步提高稳定性，建议把当前单一 `script_converter` 拆成两步：

1. `script_stager`
   - 输入：剧本文本
   - 输出：演出规划

2. `script_converter`
   - 输入：剧本 + 演出规划 + 素材信息
   - 输出：WebGal 脚本文件

这种拆分的好处：

- 更容易调试“为什么动画这样安排”
- 更容易分别优化“导演层”和“语法落地层”
- 更容易增加 reviewer
- 出问题时更容易定位责任阶段

## 推荐实施顺序

如果只做一轮收益最高、侵入最小的优化，建议按以下顺序推进：

### 第 1 阶段

- 修改 `script_converter` prompt，强制引入演出计划思维
- 重写或补强 `animation_recipes.md`，改成更结构化的配方库
- 补“场景类型 -> 默认导演手法”知识条目

### 第 2 阶段

- 为转换结果增加演出质量校验
- 优先检查进出场、节奏强度、角色状态切换、重特效密度

### 第 3 阶段

- 视效果决定是否拆出 `script_stager`
- 如果拆分，优先保留现有 `script_converter` 作为第二阶段执行器

## 建议修改点

后续实施时，重点检查这些位置：

- `src/configs/prompts.yaml`
  - `script_converter` 的系统提示词

- `data/knowledge/skills/animation_recipes.md`
  - 动画演出配方

- `data/knowledge/skills/expression_motion_guide.md`
  - 角色表情和动作触发规则

- 如新增 reviewer：
  - `src/webgal_agent/api/workflow_definition.py`
  - `src/webgal_agent/api/task_context.py`
  - `src/webgal_agent/api/task_agents.py`
  - 以及对应 prompt / knowledge 配置

## 结论

当前最值得做的，不是继续为 `script_converter` 增加更多底层语法规则，而是：

- 增加演出规划层
- 结构化动画配方
- 增加结果级演出审校

一句话概括：

要把 `script_converter` 从“脚本翻译器”往“轻量导演 + 脚本执行器”方向推。
